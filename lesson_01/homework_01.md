## 1. Три алгоритма из вашего дня

Три ситуации, где сегодня за вас отработал алгоритм. Для каждой — три строки.

**Ситуация 1. Инкрементальная компиляция**
- Вход: таймштампы исходника и бинарника
- Правила: если таймштамп исходника новее таймштампа бинарника — файл считается изменённым, иначе — файл считается неизменным (пересоберёт даже, если к исходнику просто сделали `touch`, а содержимое не менялось)
- Результат: решение — пересобрать бинарник или пропустить пересборку

**Ситуация 2. OOM Killer**
- Вход: список процессов, пользовательские флаги под ними
- Правила: убить наименее важный процесс исходя из оценки по критериям: вес процесса (больше вес — больше приоритет на убийство), важность (системные процессы имеют коэффициент на занижение приоритета), пользовательский флаг (пользователь может сам отмечать, какие процессы трогать нельзя, а какие убивать в первую очередь)
- Результат: убийство наименее важного процесса — освобождение RAM под новый процесс

**Ситуация 3. Компиляция переменных в понятный для процессора вид**
- Вход: переменные и значения
- Правила: записывает данные в точку arena pointer, которая считается и обновляется при каждой новой переменной по формуле `arena pointer += var_size` *(так как процессор не знает конкретных названий переменных и не может ориентироваться по адресам исходя из них, компилятор преобразует переменные в отступ от начальной точки — например, `int num` первой переменной даёт arena pointer = 0, переменная занимает ячейки 0–3, а следующая переменная начнётся с 4-го байта)*
- Результат: понятная процессору семантика данных, которая решает проблему динамичного расположения в RAM *(отступы относительны и не меняются при каждой новой загрузке ПО в RAM, хотя сама область RAM каждый раз разная; в бинарнике вызов значения выглядит по схожей системе, как с массивами и индексами)*

## 2. Что будет, если данных станет больше

Возьмите одну ситуацию и опишите, что изменится при росте данных в миллион
раз: где решение начнёт задыхаться и почему.

> Если в алгоритме инкрементной компиляции станет больше входных данных, то это прям смерть. Сначала надо компилировать независимые файлы, а потом уже те, где они притянуты, иначе потребуется делать повторные перекомпиляции, так как при компиляции первого он будет учитывать неактуальный связанный второй. Для решения этой проблемы притягивается другой алгоритм, который как раз раздаёт приоритеты исходникам: какие из них нужно компилировать первыми исходя из отсутствия неактуальных зависимостей или зависимостей вовсе. Если файлов на компиляцию будет в миллион раз больше, то ему придётся давать приоритет, решая граф из миллиона зависимостей, соответственно.

## 3. Два определения своими словами

**Алгоритм —** это порядок действий с определёнными начальными данными, однозначными операциями. Обязательно должен быть конец и результат/продукт.

**Инвариант —** это условие, которое верно на протяжении всего алгоритма. Если оно неверно, то что-то не так.
